Project walkthrough

Setup, file map, and full AI assessment generation pipeline.

This guide explains how to run the VedaAI frontend and backend, what each main file does, and how an assignment moves from teacher input to structured AI output, realtime status updates, MongoDB persistence, and printable PDF export.

Quick Start

1. Install dependencies

Run this once from the repository root.

npm install

2. Create env files

Copy the examples and fill in secrets such as the OpenAI key.

copy apps\backend\.env.example apps\backend\.env
copy apps\frontend\.env.example apps\frontend\.env.local

3. Start MongoDB and Redis

The backend uses MongoDB for durable records and Redis for BullMQ job state.

docker compose up mongo redis

4. Run the app processes

Use three terminals so the API, worker, and UI stay alive together.

npm run dev:backend
npm run worker --workspace @vedaai/backend
npm run dev:frontend
Local URLs

Frontend: http://localhost:3000 or the fallback port shown by Next.js. Backend health: http://localhost:4000/api/health.

Apps And Packages

apps/frontend

Next.js 15 App Router UI. Contains the teacher dashboard, assignment creator, generated paper view, analytics dashboard, shared layout, API client, Zustand store, and realtime socket hook.

apps/backend

Express API and BullMQ worker. Handles authentication mock, validation, uploads, extraction, structured AI generation, MongoDB persistence, Socket.IO events, and PDF generation.

packages/shared-types

Shared TypeScript contracts used by both apps, including job statuses, question types, assignment payloads, realtime events, and the generated paper schema.

Workflow And Pipeline

1. Teacher input

Frontend submits title, due date, files/manual text, question rows, marks, and instructions.

2. API validation

Express validates the payload with Zod and creates a MongoDB assignment with status queued.

3. Queue job

The assignment id is pushed into BullMQ so long AI work happens outside the request cycle.

4. Text extraction

Worker extracts text from uploaded documents or uses manual text as source material.

5. AI JSON

AI service requests structured JSON only and never renders raw LLM prose directly.

6. PDF export

Generated paper is stored, then converted into a high-quality printable PDF.

7. Realtime UI

Socket.IO emits progress so the dashboard and output page update live.

AI Contract

VedaAI asks the model for strict structured JSON only. The frontend renders parsed fields from this object, never raw model text. This keeps the exam-paper page predictable, printable, and safer to style. 

{
  "title": "Quiz on Electricity",
  "subject": "Science",
  "class": "8th",
  "schoolName": "Delhi Public School, Sector-4, Bokaro",
  "timeAllowedMinutes": 45,
  "maximumMarks": 20,
  "sections": [
    {
      "title": "Section A",
      "instruction": "All questions are compulsory.",
      "questions": [
        {
          "question": "Explain the purpose of electroplating.",
          "difficulty": "easy",
          "marks": 2,
          "answer": "Electroplating deposits a layer of metal on another object using electric current.",
          "type": "Short Questions"
        }
      ]
    }
  ]
}

Docker And Deployment

Full local stack

Starts MongoDB, Redis, backend API, worker, and frontend.

docker compose up --build

Deployment process split

In production, run the API and worker as separate processes so queue load does not block HTTP traffic. Persist uploads/PDFs or replace local storage with S3-compatible object storage.

Important environment values

MONGODB_URI, REDIS_URL, OPENAI_API_KEY, OPENAI_MODEL, FRONTEND_URL, NEXT_PUBLIC_API_URL, and NEXT_PUBLIC_SOCKET_URL.

npm run build --workspace @vedaai/backend

If PowerShell blocks npm.ps1, use npm.cmd for the same commands, for example npm.cmd run build --workspace @vedaai/frontend.
